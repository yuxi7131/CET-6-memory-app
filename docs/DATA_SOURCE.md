# 数据来源说明(DATA_SOURCE)

本文记录 `data/words.json` 与 `app/js/words.js` 里那 5716 个词**是从哪来的、每个字段来自哪个源、有什么已知缺口**,做到来源可查、不编造。生成脚本是 `tools/fetch_words.py`。

## 1. 一句话结论

- 词库 = **《六级词汇表》(约 2200 词)+ 《大学英语四级大纲词汇表》(约 4500 词)的合并、去重**,共 **5716** 条。
- 同一个词若两张表都出现,优先采用六级表的释义(更细),四级表只负责补充六级表没出现的四级基础词。
- 每个字段都有出处,**没有人工编造任何释义或音标**。

## 3. 每个字段来自哪

`data/words.json` 里每条: `{"word", "phonetic", "pos", "meaning"}`。

| 字段 | 来源 | 说明 |
|---|---|---|
| `word` | 两个词表每行的**行首单词** | 统一转小写;只收单个英文单词;形如 `buzz word` 的复合词/短语整行跳过(数量极少)。 |
| `phonetic` | 同一行里方括号 `[ ]` 内的**音标**(无括号音标的极少数行也已兼容) | 一词多音时用 ` / ` 连接。源表个别显示异常的字符做了等价替换(`ә`→`ə`、`∫`→`ʃ`)。**完全没有音标则留空字符串**。 |
| `pos` | 同一行内**词性标记**(`n.` `v.` `vt.` `adj.` 等) | 旧式大纲写法 `a.`(形容词)、`ad.`(副词)统一为 `adj.`/`adv.`;多个词性用 `/` 连接(如 `v./n.`)。没有词性则留空字符串。 |
| `meaning` | 同一行内的**中文释义** | 去掉 `1. 2. 3.` 编号与 `\|\|` 之后的词组/例句部分;多个义项用 `;` 连接。 |

**注意**:合并时,若某词同时出现在四级表与六级表,**优先整词采用六级表条目**(解释更细),不把两张表的释义强行拼在一起,避免重复冗余。

**与官方大纲合并表的对照(诚实说明缺口)**:
- 上游仓库另有一份按 2016 年大纲合并的**纯词单** `CET_4+6_edited.txt`,共 8013 个不同单词,但它**没有释义字段**,不能直接作为本 App 的数据。
- 本词库覆盖其中的 **5411** 个词;未覆盖 2602 个(多为派生词/较生僻词,如 `abbreviation, abide, abolition, accountability, acclaim` 等),因为两份带中文释义的 `CETx_edited.txt` 本身未收录它们。
- 换句话说:**这不是教育部大纲 8013 词的“全量词表”**,而是"六级核心表 + 四级大纲表"的实用合并版,覆盖六级备考最常见词汇。若之后想要“官方全量 8013 词全带释义”,需要接入 ECDICT 一类的全量开放词典补词(见 §6 遗留问题)。

## 5. 解析/清洗规则(脚本做了什么)

`tools/fetch_words.py` 全部用 Python 标准库,规则如下,均在代码注释里可查:
1. 跳过表头/字母分组行。
2. 取行首单词(小写);跳过含空格的复合词头。
3. 提取方括号音标(兼容无括号音标的行)。
4. 丢弃 `||`(词组/例句)与义项编号,只保留中文核心释义。
5. 去掉释义中夹在两个汉字之间的多余空格。
6. 词性归一(`a.`→`adj.`,`ad.`→`adv.`),已有 `vt./vi.` 时丢弃笼统 `v.`。
7. 先处理六级表、后处理四级表,四级表里重复的词不追加 → 得到 5716 个唯一词,按字母序输出。

## 6. 遗留问题 / 如何做得更好

- **覆盖不全**:距“官方 2016 大纲 8013 词全量”还缺约 2600 词(多是派生词/低频词)。当前版是一个够用、字段齐的“四级+六级”实用词库,完全满足里程碑 M1 的“≥4000 词、word/meaning 非空且唯一”。
- **许可**:上游仓库无显式 LICENSE。如需正式分发,建议切到 **ECDICT(MIT)** 系数据:用 ECDICT 的 `tag` 字段筛 `cet6`,可拿全量大纲词 + 标准音标 + 中文,生成脚本的解析部分替换、输出契约不变。
- **音标风格**:源表以英式音标为主(含少量 OCR 级字符噪声),未做美/英统一;Spec 中“美音优先”可在后续接入美音音标或 TTS 时再处理。
- **个别数据小错**:源表本身偶有笔误(如 `abolish` 标成 `n.`),均按源保留,未人工“修正”。
